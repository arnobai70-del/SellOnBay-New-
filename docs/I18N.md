# Multi-language support: phase 1 and phase 2 report

Branch: `feat/i18n`. Not merged, not deployed, no database change (settings live in `app_settings`; nothing is written until an admin
saves). Every language except English starts **unpublished**: after deployment visitors see exactly today's English site until an admin
publishes a language in Admin › Language Management.

## How it works

| Part | Where |
|---|---|
| Languages (8 built-in: en, bn, ar (RTL), hi, es, fr, de, pt), address rules | `lib/i18n/config.ts` (pure, tested) |
| English source words (interface + every admin-editable page word from `lib/content/registry.ts`) | `lib/i18n/messages/en.ts`, `lib/i18n/catalog.ts` |
| Machine-drafted translations (loaded only for the language asked for) | `lib/i18n/messages/<code>.ts` |
| Admin edits (draft, publish, unpublish), language list | `lib/i18n/store.ts` (`app_settings`: `i18n:languages`, `i18n:draft:<code>`, `i18n:pub:<code>`) |
| Request language | `proxy.ts` (`/bn/…` prefix on public pages, saved choice elsewhere) → header → `lib/i18n/server.ts` |
| SEO | `lib/i18n/seo.ts`: own canonical per language, `hreflang` + `x-default`, `og:locale`, translated page/product SEO words; sitemap alternates |
| Switcher | `components/i18n/LanguageSwitcher.tsx` in the top bar, footer and dashboards (shown once a second language is live) |
| Admin | `/admin/languages`: Languages, Translations, Product words, Page SEO, Missing translations |

- **Addresses:** English keeps every current address (no prefix), so links and rankings stay. Other languages: `/bn/websites`, `/ar/help`…
  `/en/…` redirects (308) to the plain address. An off or unpublished language's addresses are 404.
- **Choice:** cookie `sob_lang` (a year; kept through sign-in and sign-out), saved to the account (`user_metadata.lang`) when signed in and
  restored on sign-in on another device. A visitor with a saved choice is sent to that language's address; bots never are.
- **Fallback:** admin's published word → machine draft → English. Never a key or an empty space. Placeholders (`{keep}`, `{n}`…) must match.
- **RTL:** `<html lang dir>` is set on the server; Arabic renders right to left.
- **Never translated:** prices (USD), amounts, IDs, order and payment references, URLs, database identifiers.

## Phase 2: every screen, email and error (November 2026)

All seven languages stay **unpublished**. Every bundled translation is a **machine draft, not reviewed**: review it in Admin › Language
Management before you publish a language.

- **Words in the code.** Interface words are written in English as `tx('…')` (server: `getI18n()`, client: `useTx()`) or `<T s={'…'} />`.
  The English text is the key, so a missing word shows English, never a key. `npm run i18n:extract` lists them in
  `lib/i18n/strings/catalog.json` (generated; Prettier ignores it), and `lib/i18n/strings/<lang>.json` holds each language.
  `tests/unit/i18n-strings.test.ts` fails when the catalogue is stale, a language lacks a word or a `{placeholder}` differs.
  There are 2,965 strings, complete in bn, ar, hi, es, fr, de and pt.
- **Codemods** (kept for later screens): `scripts/i18n-codemod.mjs` handles JSX text and the placeholder, title, aria-label and alt
  attributes. `scripts/i18n-codemod-literals.mjs` handles literals in rendered positions (`?:`, `&&`, `||`, text props).
  `scripts/i18n-add.mjs` merges a translation chunk.
- **Emails** (`emails/templates.ts`): every sentence goes through `tx()`. A person gets mail in the language saved on their account
  (`user_metadata.lang`), and only while that language is published (`lib/i18n/recipient.ts`); otherwise English. The English output is
  identical to before. Names, amounts and dates from the payload are never translated. A template a Super Admin published in Admin › CMS
  still wins for every reader. The in-app notification list follows the page's language.
- **API errors**: `jsonT()` (`lib/i18n/jsonT.ts`) translates `error` for the request's language when the catalogue has the message. That
  covers 202 literals in `app/api`, 239 in `lib/`, the auth guards and `readJson`. Messages with numbers filled in stay English. Error
  codes, ids and amounts are untouched.
- **Legal pages**: the frame (contents list, headings) is translated. The legal text itself stays English, marked `lang="en"
  dir="ltr"`, with a notice in the page's language that only the English text applies. No legal translation drafts were made (see
  "Still open").
- **Language offer**: on an English public page, a visitor whose browser prefers a *published* language sees a one-line offer in that
  language (`components/i18n/LanguageSuggest.tsx`). It never redirects. "Keep English" is remembered.
- **Performance**: the browser gets only the words its page can use. The root layout sends the "public" client words; the `(dash)`
  layout adds the dashboard words. Measured for Bengali, about 14.5 KB gzip on a public page (it was 64 KB before the split). An
  English page sends nothing.
- **Screenshots**: `docs/i18n/screenshots/` (en, bn, ar home at 390 and 1280 px), made by
  `I18N_SCREENSHOTS=docs/i18n/screenshots npx playwright test tests/e2e/i18n.spec.ts`.

### Still open

1. **Legal translations**: they need a qualified legal translator and a lawyer's review before anything is published. Until then the
   pages show English with the notice.
2. **Product words**: names, descriptions and categories are the sellers' data and are translated per listing in Admin › Language
   Management › Products.
3. About 20 literals the codemods could not place safely: spaced fragments such as `" · draft"`, plus non-async server components. The
   list is printed by `scripts/i18n-codemod-literals.mjs --dry`.
4. Synchronous error builders stay English: `parseWith` default messages and the file-size limit in `lib/delivery/serve.ts`.
5. Native-speaker review of every machine draft before publishing a language.

## Performance note

The public pages that were pre-built (home, help, sell, legal) now render on each request, because the language comes from the request.
Their data reads are cached as before. If needed later, these pages can be cached per language.

## Rollout (needs the owner's approval)

No migration. Merge, build the zip, deploy. Visitors see no change (English only). Then in Admin › Language Management: review a language's
machine drafts in Translations, publish its edits, and tick Published for the language.
