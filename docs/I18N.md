# Multi-language support: phase 1 report

Branch: `feat/i18n`. Not merged, not deployed, no database change (settings live in `app_settings`; nothing is written until an admin
saves). Every language except English starts **unpublished**: after deployment visitors see exactly today's English site until an admin
publishes a language in Admin › Language Management.

## How it works

| Part | Where |
|---|---|
| Languages (8 built-in: en, bn, ar (RTL), hi, es, fr, de, pt), address rules | `lib/i18n/config.ts` (pure, tested) |
| English source words (interface + every admin-editable page word from `lib/content/registry.ts`) | `lib/i18n/messages/en.ts`, `lib/i18n/catalog.ts` |
| Machine-drafted translations (loaded only for the language asked for) | `lib/i18n/messages/<code>.ts` |
| Admin edits (draft, publish, unpublish), language list | `lib/i18n/store.ts` (`app_settings`: `i18n:languages`, `i18n:draft:<code>`, `i18n:pub:<code>`) |
| Request language | `proxy.ts` (`/bn/…` prefix on public pages, saved choice elsewhere) → header → `lib/i18n/server.ts` |
| SEO | `lib/i18n/seo.ts`: own canonical per language, `hreflang` + `x-default`, `og:locale`, translated page/product SEO words; sitemap alternates |
| Switcher | `components/i18n/LanguageSwitcher.tsx` in the top bar, footer and dashboards (shown once a second language is live) |
| Admin | `/admin/languages`: Languages, Translations, Product words, Page SEO, Missing translations |

- **Addresses:** English keeps every current address (no prefix), so links and rankings stay. Other languages: `/bn/websites`, `/ar/help`…
  `/en/…` redirects (308) to the plain address. An off or unpublished language's addresses are 404.
- **Choice:** cookie `sob_lang` (a year; kept through sign-in and sign-out), saved to the account (`user_metadata.lang`) when signed in and
  restored on sign-in on another device. A visitor with a saved choice is sent to that language's address; bots never are.
- **Fallback:** admin's published word → machine draft → English. Never a key or an empty space. Placeholders (`{keep}`, `{n}`…) must match.
- **RTL:** `<html lang dir>` is set on the server; Arabic renders right to left.
- **Never translated:** prices (USD), amounts, IDs, order and payment references, URLs, database identifiers.

## Not done yet (phase 2)

The framework, admin and SEO are complete; the words of these places are still English and show in English in every language:

1. The body text of public pages not built from the page registry (websites list filters, website detail labels other than the four
   registry ones, domains, sellers, sell, help articles, buyer protection, guides, sign-in forms, cart and checkout).
2. The inner pages of the buyer, seller and affiliate dashboards and every admin screen (menus are translated).
3. Emails (`emails/templates.ts`) and server error messages.
4. Legal pages: translations must be reviewed by a lawyer before publishing.

Each needs its words moved into the catalogue (`t('…')`) and the seven drafts added; Admin › Missing translations then shows them.

## Performance note

The public pages that were pre-built (home, help, sell, legal) now render on each request, because the language comes from the request.
Their data reads are cached as before. If needed later, these pages can be cached per language.

## Rollout (needs the owner's approval)

No migration. Merge, build the zip, deploy. Visitors see no change (English only). Then in Admin › Language Management: review a language's
machine drafts in Translations, publish its edits, and tick Published for the language.
